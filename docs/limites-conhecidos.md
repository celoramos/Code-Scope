# Limites conhecidos

O que o Code Scope ainda não faz, ou faz diferente do que você poderia esperar.

- As chamadas de baixo na pilha mostram as variáveis simples, os 8 primeiros itens de arrays e listas e os objetos como texto, com os 3 primeiros campos (`No {valor: 5, esq: No, dir: null}`), sem setas. São lidas no máximo 12 chamadas.
- Só objetos de classes declaradas no arquivo que está sendo debugado são desenhados, no máximo 40 por passo. Objetos dentro de uma matriz mostram o valor principal na célula e o cartão embaixo. Enums declarados no arquivo aparecem como a constante (`Cor.AZUL`); enums de bibliotecas ficam de fora.
- O JavaScript não mostra a identidade dos objetos, então a pergunta vai para o próprio programa (`a === b`); entre passos, o objeto mantém a identidade pelos caminhos que levam a ele. Uma lista refeita do zero num passo só pode parecer feita de objetos novos.
- Uma parte de condição que chama um método só é avaliada quando o método apenas lê (`len`, `.length`, `.size()`, `.equals`, `.get`...); senão, aparece "não dá para saber antes".
- Variáveis escondidas (um nome escondendo outro) são reconhecidas em blocos do JavaScript e em parâmetros com o nome de um campo. Java e Python não têm escopo de bloco para variáveis locais.
- JavaScript no navegador é testado com o Chrome no VS Code, no Windows, no Linux e no macOS. No VSCodium no Linux (CI), o debugger de JavaScript que vem com ele não se conectou ao Chrome ("Could not attach to main target"), então o navegador não está verificado lá.
- No modo genérico, só aparecem coleções que o debugger marca como indexadas ou cujo tamanho está escrito no valor.
- Arrays de três dimensões mostram as 8 primeiras camadas, cada uma como matriz. Da quarta dimensão em diante, o resto aparece como texto.
- `std::map`, `std::set`, `std::stack`, `std::queue`, `std::deque`, `std::list` e `std::priority_queue` precisam de um gdb com os pretty-printers (`-enable-pretty-printing` em `setupCommands`); sem eles, ficam de fora. `std::vector`, inclusive `std::vector<bool>`, funciona com ou sem eles. No Linux, se o gdb escreve `No module named 'math'` (ou outro módulo do Python), ele carregou a biblioteca do Python errada, quase sempre porque o `LD_LIBRARY_PATH` aponta para outro Python (conda, pyenv, imagens de CI): os pretty-printers se perdem. Abra o VS Code sem essa variável, ou aponte o `miDebuggerPath` para um script que rode `env -u LD_LIBRARY_PATH gdb "$@"`.
- Em Go, entrar no `fmt` ou passar do fim do `main` mostra código de biblioteca. Um ponteiro aparece de novo como objeto novo depois que uma chamada volta.
- Texto com mais de 500 caracteres é cortado. Um objeto do JavaScript com dezenas de milhares de chaves com nome leva segundos por passo, porque o js-debug não pagina propriedades com nome; arrays, `Map` e `Set` são lidos uma página por vez.
- Um GIF mostra no máximo 80 passos, espalhados pela execução. Um `@expect` passa assim que um passo tem todos os valores certos, mesmo que eles mudem depois.
- Uma lista que ganha ou perde vários itens num passo é animada quando eles formam um bloco (`addAll`, `extend`, `splice`); itens que entram em lugares diferentes aparecem como redimensionamento.
- Fora de matrizes, um inteiro vira seta quando o código usa ele como posição: dentro de colchetes (`v[i]`), em `get(i)`, `insert(i, x)` e parecidos, comparado com o tamanho, ou na conta de outra posição (`meio = (inicio + fim) / 2`). Nomes em `codeScope.valueNames` nunca viram seta. Sem o arquivo-fonte, vira seta todo inteiro que caiba nos índices.
- Pilha e fila são reconhecidas pelo uso da variável na função parada, e pelo arquivo inteiro quando essa função não diz nada. Uma coleção usada por uma função auxiliar pode mudar de papel quando o programa para lá.
- Se você usar F5 (continue) entre breakpoints, o painel avisa e mostra a diferença acumulada entre as duas paradas: ele não vê as linhas do meio.
- O plugin JetBrains cobre só Java (configurações em Settings > Tools > Code Scope). O modo apresentação e o **Open a Sample** ficam em **Tools > Code Scope**; a pasta dos exemplos abre como projeto simples, então escolha um JDK se a IDE pedir. O F8 do IntelliJ também para no `}` que fecha um `if`, que o VS Code pula, então o mesmo programa pode levar alguns passos a mais lá. Depois do F7, o valor que uma chamada devolveu não aparece no IntelliJ.
